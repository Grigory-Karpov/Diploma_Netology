# План автоматизации тестирования приложения «Мобильный хоспис»

## 1. Перечень автоматизируемых сценариев

В рамках данного этапа будут автоматизированы проверки основного функционала приложения (UI-тесты).

**Границы приложения (что тестируем):**
*   Экран авторизации (Login screen).
*   Главный экран (Main screen) с лентой новостей.
*   Экран управления новостями (Control panel / News).
*   Экран «Тематические цитаты» (Our Mission).
*   Экран информации о приложении (About).
*   Навигация через боковое меню (Burger menu).

Детальное описание шагов для каждого теста, ожидаемые результаты и статус прохождения будут зафиксированы в документах:
*   **Чек-лист проверок:** файл `Check.xlsx`
*   **Тест-кейсы:** файл `Cases.xlsx`

*Примечание: Автоматизируются позитивные и негативные сценарии (ввод валидных и невалидных данных при авторизации, корректность отображения элементов UI, переходы между экранами).*

## 2. Перечень используемых инструментов с обоснованием выбора

1.  **Android Studio** — официальная и наиболее стабильная интегрированная среда разработки (IDE) для Android от Google. Позволяет запускать эмуляторы, анализировать код и писать тесты "в одном окне".
2.  **Java** — язык программирования, на котором написана значительная часть экосистемы Android, тесты будут реализованы на нем.
3.  **JUnit 4** — базовый фреймворк для написания и запуска тестов. Проверенный временем стандарт индустрии.
4.  **Espresso** — основной фреймворк от Google для написания UI-тестов Android-приложений. Работает очень быстро, так как синхронизируется с жизненным циклом приложения и имеет прямой доступ к элементам экрана.
5.  **Allure Report** — мощный инструмент для генерации наглядных отчетов о тестировании. Позволяет легко читать результаты прогонов, прикреплять скриншоты (что критически важно при падении UI-тестов) и собирать подробную статистику.
6.  **Git / GitHub** — система контроля версий и сервис хостинга ИТ-проектов. Необходимы для сохранения истории изменений и сдачи дипломного проекта руководителю.

## 3. Перечень и описание возможных рисков при автоматизации

1.  **Проблемы с настройкой окружения:** версии зависимостей (Gradle, Espresso, Allure) могут конфликтовать друг с другом. Решение: строгое соблюдение версионирования библиотек.
2.  **Нестабильность UI-тестов (Flaky tests):** тесты могут периодически падать из-за задержек анимации или скорости сети. Решение: использование `IdlingResource` в Espresso для ожидания готовности интерфейса.
3.  **Изменение ID элементов приложения:** если разработчики изменят идентификаторы (`R.id...`) элементов интерфейса, тесты упадут. Решение: использование Page Object паттерна для минимизации мест, где нужно менять локаторы.

## 4. Интервальная оценка с учётом рисков (в часах)

*   Настройка тестового окружения (установка библиотек, настройка Allure, запуск эмулятора) — 8-12 часов.
*   Написание чек-листа и тест-кейсов (ручное тестирование) — 12-16 часов.
*   Написание UI-тестов (автоматизация сценариев) — 20-30 часов.
*   Настройка генерации отчетов Allure и отладка упавших тестов — 8-12 часов.
*   Подготовка документации, упаковка и сдача проекта — 4-8 часов.

**Итого:** примерное время выполнения проекта составляет от 52 до 78 часов рабочего времени.

## 5. План сдачи работ

1.  **Этап 1 (Планирование):** Ручное тестирование, подготовка файлов `Plan.md`, `Check.xlsx`, `Cases.xlsx`. Отправка репозитория руководителю (первые 7 дней работы).
2.  **Этап 2 (Автоматизация):** После утверждения первого этапа — настройка проекта, написание кода UI-тестов с использованием Espresso.
3.  **Этап 3 (Отчетность):** Подключение Allure, прогон тестов, генерация `allure-results.zip`, написание `README.md` с инструкцией по запуску и `Result.md` со сравнением ручного и авто-тестирования. Финальная сдача диплома.
